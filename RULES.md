# HeadVoice safety rules

HeadVoice is a research and education prototype, not a medical device. These rules are enforced in code, and each one is covered by automated tests. Rules 1 to 11 are tested in `tests/test_safety.py` (test names start with the rule number); the adaptation guards under rules 7 and 9 are also tested in `tests/test_server.py`.

1. **Code owns the state.** The gesture state machine (`src/headvoice/interaction/state_machine.py`) is a pure function. No agent output can change its state. Agent tool calls can only change bounded profile parameters, and a menu or layout change waits until no gesture is in progress.
2. **Fail closed.** No face, low quality, optical-flow landmarks, a turned head or a frozen camera feed means no selection and no speech. Losing the signal while a choice is armed cancels it.
3. **Debounce.** One physical tilt produces at most one highlight. A tilt must be held past the threshold, then return toward neutral before it can count again, with a refractory window per direction.
4. **Confirm before speaking.** Speech happens only after Armed to Speaking, which needs both eyes closed for the full long-blink time on a single highlighted option, on good frames, starting after the eyes were seen open. A long blink with nothing highlighted only shows other messages. Eye closure is ignored while the head is pitched down. One function (`_confirm`) is the only place a speak event exists; the dwell mode used as evaluation baseline B goes through it too.
5. **Undo.** The undo gesture (double blink, or tilt down in left/right layouts when calibration chose it) during Highlighting or Armed cancels with no speech.
6. **Stale-result guard.** Every agent request carries `session_id` and a rising `epoch`. Older answers are discarded and logged.
7. **Bounded agent.** Agent tool calls are checked against `config/agent_bounds.json` (layouts, timing ranges, tilt sensitivity 0.5 to 1.0). Out-of-bounds values and unknown tools are rejected and logged. At most 3 tool calls per invocation, enforced in the Lambda and again on the device. Every reversible change has a one-step rollback. A layout chosen by a helper in the helper panel cannot be changed by the agent for that session.
8. **Tool tiers.** `speak_message` and `send_caregiver_alert` cannot be called by the agent at all. `access_raw_video` is forbidden and every attempt is logged. `request_recalibration` only shows a prompt the user must accept.
9. **Action cap and pacing.** At most 3 agent adaptations per 2 minutes (`max_actions_per_window`, `action_window_s`); extra actions are rejected. No adaptation in a session's first minute except for a signal-quality drop; only deliberate tilts (half the threshold, held 0.2 s) count as attempts; a new decision waits until the previous change's outcome has been measured.
10. **Offline fallback.** A network failure, timeout or invalid answer falls back to the fixed phrase list without blocking the UI; a failed agent call keeps the current settings and is logged. Installs without a cloud connection adapt with the on-device rule policy.
11. **Privacy.** Only numbers and short labels derived from `FrameFeatures` leave the device (`src/headvoice/io/privacy.py` checks every outbound payload, and the supervise Lambda checks again). The camera picture is never stored or uploaded; the camera window is served on localhost only. The only exception is the calibration clip, uploaded only with explicit consent and deleted as soon as it is read. The user's own messages never leave the computer.

Known gap (reported in `docs/report.md`, failure 10): the agent can still change settings on a signal-quality trigger, where only "hold still" or "no change" should be allowed, and can switch layouts back and forth. Rules 7 and 9 bound these changes but do not prevent them.
